# Deploying Paperclip on Coolify

Step-by-step guide for deploying Paperclip on [Coolify](https://coolify.io) with Claude Max subscription auth and OpenClaw integration.

## Prerequisites

- A running Coolify server (self-hosted or managed)
- Tailscale or other VPN for private access (recommended)
- A Claude Max subscription for `CLAUDE_CODE_OAUTH_TOKEN`

## 1. Generate Claude Code OAuth Token

On your local machine (where you're logged into Claude Max):

```sh
claude setup-token
```

Copy the token — you'll paste it into Coolify's environment variables.

## 2. Create the Shared Docker Network

SSH into the Coolify host and create the network that Paperclip and OpenClaw will share:

```sh
docker network create --attachable paperclip-openclaw
```

This must exist before deploying either stack.

## 3. Deploy in Coolify

1. In the Coolify dashboard, create a new **Docker Compose** resource
2. Set the deployment mode to **Standard**
3. Paste the contents of `docker-compose.yml` from this repo (or point to the repo)
4. Coolify will auto-generate values for `SERVICE_FQDN_PAPERCLIP_3100` and `SERVICE_PASSWORD_64_AUTHSECRET`

## 4. Set Environment Variables

In the Coolify UI, set these environment variables for the Paperclip service:

| Variable | Value | Notes |
|---|---|---|
| `CLAUDE_CODE_OAUTH_TOKEN` | *(from step 1)* | Do **not** set `ANTHROPIC_API_KEY` — it would override subscription auth and bill via API |

All other variables (`SERVICE_FQDN_*`, `SERVICE_PASSWORD_*`, `SERVICE_PASSWORD_64_*`, deployment mode, host, port) are either auto-generated by Coolify or have defaults in the compose file.

### MinIO (S3-compatible storage)

The compose file includes a MinIO service for file storage. Coolify auto-generates the MinIO credentials (`SERVICE_PASSWORD_MINIO_ROOT_USER` and `SERVICE_PASSWORD_64_MINIO_ROOT_PASSWORD`), which are shared between the MinIO server and Paperclip's S3 client config. A one-shot `minio-init` container creates the `paperclip` bucket on first deploy.

No manual configuration is needed — the S3 endpoint, bucket, and credentials are all wired up in the compose file.

## 5. First Boot

On first deploy, the entrypoint script automatically:

1. Creates the Claude Code onboarding flag (`~/.claude.json`) to skip the interactive wizard
2. Runs `npx paperclipai onboard --yes` to initialize the Paperclip instance

The health check has a 60-second `start_period` to allow onboarding to complete.

**After the service is healthy**, create the first admin user:

```sh
docker exec <container-name> npx paperclipai auth bootstrap-ceo
```

This prints an invite link. Open it to create your admin account.

## 6. OpenClaw Integration

**Prerequisite**: OpenClaw must already be deployed as a separate Coolify stack on the same host.

To connect Paperclip to an OpenClaw instance running on the same Coolify host:

### OpenClaw Environment Changes

In the Coolify UI, update these env vars on the **OpenClaw** service and redeploy:

| Variable | Value | Notes |
|---|---|---|
| `OPENCLAW_GATEWAY_BIND` | `lan` | Binds to the container's LAN interface instead of localhost |
| `HOOKS_ENABLED` | `true` | Enables the webhook system Paperclip uses |
| `HOOKS_TOKEN` | *(generate a secure token)* | Shared secret for webhook auth |

### OpenClaw Network

Add the shared network to the OpenClaw stack's compose file (or via Coolify UI):

```yaml
networks:
  openclaw-bridge:
    external: true
    name: paperclip-openclaw
```

And attach the OpenClaw service to this network. After redeploying, both services can reach each other by container name on the `paperclip-openclaw` network.

### Paperclip Agent Configuration

In the Paperclip UI, configure your agent adapters:

- **claude_local** — Uses `CLAUDE_CODE_OAUTH_TOKEN` for Claude Code agent dispatch
- **openclaw_gateway** — Points to the OpenClaw container on the shared network (e.g., `http://openclaw:port`)

## 7. Maintenance

### Token Rotation

When your Claude Max token expires or you need to rotate it:

1. Run `claude setup-token` locally to generate a new token
2. Update `CLAUDE_CODE_OAUTH_TOKEN` in the Coolify UI
3. Redeploy the service

### Image Updates

The `docker-compose.yml` uses `ghcr.io/birdcar/paperclip-docker:latest`. To update:

1. In Coolify, trigger a redeploy — it will pull the latest image
2. The entrypoint is idempotent; it skips onboarding if config already exists

### Backups

The `paperclip-data` volume holds all persistent state (config, database, secrets, attachments). Back it up regularly:

```sh
docker run --rm -v paperclip-data:/data -v $(pwd):/backup alpine tar czf /backup/paperclip-backup.tar.gz -C /data .
```
