# Deploying Paperclip on Coolify

Deploy Paperclip on [Coolify](https://coolify.io) with Claude Max subscription auth, MinIO storage, and OpenClaw integration.

This guide provides both UI and API instructions. All API examples use the Coolify REST API (`/api/v1`). Authenticate every request with `Authorization: Bearer <token>` — generate a token in the Coolify UI under **Keys & Tokens > API Tokens** with `read`, `write`, and `deploy` abilities.

## Prerequisites

- A running Coolify instance with at least one server configured
- A Claude Max subscription (for `CLAUDE_CODE_OAUTH_TOKEN`)
- SSH access to the Coolify host (for network creation and bootstrap)
- The Coolify server UUID, project UUID, and environment name (find these via `GET /api/v1/servers` and `GET /api/v1/projects`)

## 1. Generate Claude Code OAuth Token

On a local machine where you're logged into Claude Max:

```sh
claude setup-token
```

Save the token — it's needed in step 4.

## 2. Create the Shared Docker Network

SSH into the Coolify host and create the network that Paperclip and OpenClaw share:

```sh
docker network create --attachable paperclip-openclaw
```

This must exist before deploying either stack. Verify with `docker network ls | grep paperclip-openclaw`.

## 3. Create the Service

### Via API

```sh
# Base64-encode the compose file
COMPOSE_B64=$(base64 -w0 docker-compose.yml)  # Linux
# COMPOSE_B64=$(base64 -i docker-compose.yml)  # macOS

curl -X POST "https://<coolify>/api/v1/services" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "server_uuid": "<server-uuid>",
    "project_uuid": "<project-uuid>",
    "environment_name": "production",
    "name": "paperclip",
    "description": "Paperclip AI agent orchestration with MinIO and OpenClaw",
    "docker_compose_raw": "'"$COMPOSE_B64"'",
    "instant_deploy": false
  }'
```

**Response** returns `{ "uuid": "<service-uuid>" }`. Save this UUID for subsequent steps.

### Via UI

1. Create a new **Docker Compose** resource in your project
2. Set deployment mode to **Standard**
3. Paste the contents of `docker-compose.yml` from this repo

Coolify auto-generates values for `SERVICE_FQDN_PAPERCLIP_3100`, `SERVICE_PASSWORD_64_AUTHSECRET`, `SERVICE_USER_MINIO`, and `SERVICE_PASSWORD_64_MINIO`.

## 4. Set Environment Variables

The only user-supplied variable is `CLAUDE_CODE_OAUTH_TOKEN`. All other variables are either auto-generated by Coolify or have defaults in the compose file.

**Do not set `ANTHROPIC_API_KEY`** — it takes precedence over the OAuth token and would bill via API instead of using the Max subscription.

### Via API

```sh
curl -X PATCH "https://<coolify>/api/v1/services/<service-uuid>/envs/bulk" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "data": [
      { "key": "CLAUDE_CODE_OAUTH_TOKEN", "value": "<token-from-step-1>" }
    ]
  }'
```

### Via UI

Add `CLAUDE_CODE_OAUTH_TOKEN` in the service's **Environment Variables** tab.

### Auto-generated variables

| Variable | Type | Purpose |
|---|---|---|
| `SERVICE_FQDN_PAPERCLIP_3100` | FQDN | Domain routing to port 3100 via Coolify's proxy |
| `SERVICE_PASSWORD_64_AUTHSECRET` | Password (64 char) | BetterAuth session secret |
| `SERVICE_USER_MINIO` | Username | MinIO root user |
| `SERVICE_PASSWORD_64_MINIO` | Password (64 char) | MinIO root password |

These are generated on service creation and shared across all containers in the stack. No manual configuration needed.

## 5. Deploy

### Via API

```sh
# Trigger deployment
curl -X GET "https://<coolify>/api/v1/deploy?uuid=<service-uuid>" \
  -H "Authorization: Bearer <token>"
```

**Response**: `{ "deployments": [{ "message": "Deployment queued.", "resource_uuid": "...", "deployment_uuid": "<deployment-uuid>" }] }`

Poll for completion:

```sh
curl -X GET "https://<coolify>/api/v1/deployments/<deployment-uuid>" \
  -H "Authorization: Bearer <token>"
```

The `status` field progresses through: `queued` → `in_progress` → `finished` (or `failed`).

### Via UI

Click **Deploy** on the service page.

## 6. First Boot

On first deploy, the entrypoint script automatically:

1. Creates `/paperclip/.claude.json` with `{"hasCompletedOnboarding":true}` to skip Claude Code's interactive wizard
2. Runs `npx paperclipai onboard --yes` to initialize the Paperclip instance
3. The `minio-init` container creates the `paperclip` bucket in MinIO

The health check has a 60-second `start_period` to allow onboarding to complete before Coolify marks the service as unhealthy.

**After the service is healthy**, create the first admin user:

```sh
ssh <coolify-host> "docker exec \$(docker ps -qf name=paperclip) npx paperclipai auth bootstrap-ceo"
```

This prints an invite link. Open it to create your admin account.

## 7. OpenClaw Integration

**Prerequisite**: OpenClaw must already be deployed as a separate Coolify stack on the same host.

### OpenClaw Environment Changes

Update these env vars on the **OpenClaw** service and redeploy:

| Variable | Value | Purpose |
|---|---|---|
| `OPENCLAW_GATEWAY_BIND` | `lan` | Binds gateway to the container's LAN interface instead of localhost |
| `HOOKS_ENABLED` | `true` | Enables the webhook system Paperclip uses |
| `HOOKS_TOKEN` | *(generate a secure token)* | Shared secret for webhook auth |

#### Via API

```sh
# Find the OpenClaw service UUID
curl -X GET "https://<coolify>/api/v1/services" \
  -H "Authorization: Bearer <token>"

# Set env vars
curl -X PATCH "https://<coolify>/api/v1/services/<openclaw-uuid>/envs/bulk" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "data": [
      { "key": "OPENCLAW_GATEWAY_BIND", "value": "lan" },
      { "key": "HOOKS_ENABLED", "value": "true" },
      { "key": "HOOKS_TOKEN", "value": "<secure-token>" }
    ]
  }'

# Redeploy OpenClaw
curl -X GET "https://<coolify>/api/v1/deploy?uuid=<openclaw-uuid>" \
  -H "Authorization: Bearer <token>"
```

### OpenClaw Network

Add the shared network to the OpenClaw stack's compose file:

```yaml
networks:
  openclaw-bridge:
    external: true
    name: paperclip-openclaw
```

Attach the OpenClaw service to this network, then redeploy. Both services can then reach each other by container name on the `paperclip-openclaw` network.

### Paperclip Agent Configuration

In the Paperclip UI, configure your agent adapters:

- **claude_local** — Uses `CLAUDE_CODE_OAUTH_TOKEN` for Claude Code agent dispatch
- **openclaw_gateway** — Points to the OpenClaw container on the shared network (e.g., `http://openclaw:port`)

## 8. Maintenance

### Token Rotation

```sh
# Generate new token locally
claude setup-token

# Update via API
curl -X PATCH "https://<coolify>/api/v1/services/<service-uuid>/envs/bulk" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{ "data": [{ "key": "CLAUDE_CODE_OAUTH_TOKEN", "value": "<new-token>" }] }'

# Redeploy
curl -X GET "https://<coolify>/api/v1/deploy?uuid=<service-uuid>" \
  -H "Authorization: Bearer <token>"
```

### Image Updates

The compose file uses `ghcr.io/birdcar/paperclip-docker:latest`. To pull the latest image and redeploy:

```sh
# Restart with latest image
curl -X GET "https://<coolify>/api/v1/services/<service-uuid>/restart?latest=true" \
  -H "Authorization: Bearer <token>"
```

The entrypoint is idempotent — it skips onboarding if config already exists.

### Backups

The `paperclip-data` and `minio-data` volumes hold all persistent state. Back them up regularly:

```sh
ssh <coolify-host> "docker run --rm -v paperclip-data:/data -v /tmp:/backup alpine tar czf /backup/paperclip-backup.tar.gz -C /data ."
ssh <coolify-host> "docker run --rm -v minio-data:/data -v /tmp:/backup alpine tar czf /backup/minio-backup.tar.gz -C /data ."
```

### Service Status

```sh
# Check service details
curl -X GET "https://<coolify>/api/v1/services/<service-uuid>" \
  -H "Authorization: Bearer <token>"

# List all resources on the server
curl -X GET "https://<coolify>/api/v1/servers/<server-uuid>/resources" \
  -H "Authorization: Bearer <token>"
```
